# ATS 아키텍처 제안서

> 작성일: 2026-10-11 · 상태: 제안 (확정 전)
> API 한도는 2026년 중반까지의 공개 정보 기준입니다. 가입 전에 각 서비스의 현재 약관을 한 번 더 확인하세요.

## 0. 요구사항 정리

| # | 요구사항 | 설계에 주는 영향 |
|---|---|---|
| R1 | 브라우저 입력폼에서 동작 | 확장 프로그램 또는 OS 레벨 입력 제어 |
| R2 | Discord, Slack 등 **데스크톱 앱 내부**에서도 동작 | 브라우저 확장만으로는 불가능 → OS 레벨 프로세스 필수 |
| R3 | 외부 번역 API는 **전면 무료**일 때만 사용 | 초과 과금이 없는 플랜만 채택, 공급자 교체 가능 구조 |
| R4 | 단축키 일괄 번역 / 실시간 번역을 옵션으로 선택 | 두 가지 입력 파이프라인, 공통 번역 코어 |
| R5 | 로컬 전용, 배포 없음 | 서명/자동 업데이트/스토어 등록 불필요 → 개발용 확장 로드로 충분 |

대상 OS: **Windows** (2026-10-11 확정). Windows 10/11은 WebView2가 기본 탑재돼 Tauri 실행에 추가 설치가 필요 없고, 키 시뮬레이션은 Win32 `SendInput`(enigo), 데스크톱 실시간 모드는 UI Automation을 사용합니다.

## 1. 접근 방식 비교

Discord와 Slack 데스크톱 앱은 Electron 앱이지만, 외부에서 확장을 주입할 수 없습니다. 그래서 R2 때문에 **"브라우저 확장 단독" 안은 탈락**입니다.

| 방식 | 브라우저 | Discord/Slack 앱 | 단축키 모드 | 실시간 모드 | 난이도 |
|---|---|---|---|---|---|
| A. 브라우저 확장 단독 | ◎ | ✕ | ◎ | ◎ (DOM 직접 접근) | 낮음 |
| B. 데스크톱 앱 단독 (Tauri/Electron) | ○ (클립보드 방식) | ○ (클립보드 방식) | ◎ | △ (접근성 API 필요) | 중간 |
| C. **하이브리드: 데스크톱 앱 + 브라우저 확장** | ◎ | ○ | ◎ | 브라우저 ◎ / 앱 △ | 중간~높음 |

### 1-1. 단축키 일괄 번역은 어디서나 같은 방식으로 됩니다 (OS 레벨)

```
[사용자가 Ctrl+Alt+T]
  → 기존 클립보드 백업
  → Ctrl+A, Ctrl+C 시뮬레이션 (포커스된 입력창 전체 복사)
  → 언어 감지 → 번역
  → 클립보드에 번역문 쓰기 → Ctrl+V 시뮬레이션
  → 클립보드 원복
```

- 장점: 브라우저, Discord, Slack, 메모장 등 텍스트 입력 가능한 모든 곳에서 동일하게 동작합니다.
- 주의점: 키 시뮬레이션 사이에 약간의 지연(30~80ms)이 필요하고, 일부 앱은 Ctrl+A 동작이 다릅니다(예: 여러 줄 에디터). 앱별 예외 처리 테이블을 둡니다.

### 1-2. 실시간 번역은 "입력창을 직접 덮어쓰기"보다 "미리보기 + 확정"이 맞습니다

타이핑 중에 입력창 내용을 계속 번역문으로 바꾸면 커서 위치가 깨지고, **한글 IME 조합 중(`isComposing`)인 글자와 충돌**합니다. 그래서 실시간 모드는 다음처럼 정의하는 것을 권장합니다.

- 입력이 멈추면(디바운스 400~600ms) 번역해서 **입력창 근처에 미리보기**를 띄움
- `Tab` 또는 지정 키로 확정하면 그때 치환
- 브라우저: 확장의 content script가 `input`/`compositionend` 이벤트를 받아 처리 (정확하고 쉬움)
- 데스크톱 앱: Windows UI Automation / macOS Accessibility API로 포커스된 입력창의 텍스트를 폴링해 오버레이 창에 미리보기. Electron 앱은 접근성 트리 노출이 불완전할 수 있어 **실험 단계(Phase 4)** 로 둡니다.

## 2. 무료 번역 API 비교

R3("전면 무료")를 **"한도를 넘으면 과금이 아니라 차단되는 것"** 으로 해석했습니다.

| 서비스 | 무료 한도 | 초과 시 | 키/가입 | 품질(한↔영/일) | 판정 |
|---|---|---|---|---|---|
| **DeepL API Free** | 월 50만 자 | 차단 (과금 없음) | 가입 필요, 본인 확인용 카드 등록 | 매우 좋음 | ✅ 기본 공급자 |
| **Microsoft Translator (Azure F0)** | 월 200만 자 | 차단 (F0 티어는 과금 없음) | Azure 계정, 카드 등록 | 좋음 | ✅ 보조 공급자 |
| Google Cloud Translation | 월 50만 자 크레딧 | **과금** | 결제 계정 필수 | 좋음 | ❌ (전면 무료 아님) |
| Google 비공식 엔드포인트 (`client=gtx`) | 공식 한도 없음 | 레이트리밋/IP 차단 가능 | 키 없음 | 좋음 | △ 비상용 폴백만 (약관 회색지대, 언제든 막힐 수 있음) |
| Papago | 네이버 개발자센터 무료 API 종료, 현재 NCP 유료 | 과금 | - | 한국어 강함 | ❌ |
| MyMemory | 하루 5천 자 (이메일 파라미터 시 5만 자) | 차단 | 키 없음 | 보통 이하 | △ 폴백 |
| LibreTranslate (셀프호스팅) | 무제한 (로컬 Docker) | - | 없음 | 보통 이하 | △ 오프라인 폴백 |
| 로컬 LLM (Ollama 등) | 무제한 | - | 없음 | 모델/사양에 따라 다름 | △ 옵션 (GPU 있으면 고려) |
| Chrome 내장 Translator API | 무제한, 온디바이스 | - | 없음 | 괜찮음 | ✅ 브라우저 실시간 미리보기용 |

**사용량 감각:** 댓글 1개 평균 150자, 하루 50개 작성이면 월 약 22만 자입니다. 실시간 모드는 디바운스마다 호출되므로 단축키 모드의 3~5배가 들 수 있습니다. 그래서 실시간 미리보기는 무료/로컬 엔진(Chrome 내장, 캐시)으로, 확정 번역은 DeepL로 나누는 전략이 한도 관리에 유리합니다.

### 언어 감지

- 사용 시나리오상 **원문은 거의 항상 한국어**이므로, 1차 판정은 한글 유니코드 비율(가–힣, ㄱ–ㅣ)로 충분합니다. 비율이 임계치 이상이면 번역, 이미 외국어면 건너뜁니다(이중 번역 방지).
- 다국어 원문까지 다루려면 `eld` 또는 `franc` 같은 로컬 감지 라이브러리, 또는 DeepL의 `source_lang` 자동 감지를 사용합니다. 브라우저 쪽은 Chrome 내장 Language Detector API도 선택지입니다.
- **목표 언어**는 감지가 아니라 설정으로 정합니다: 앱/도메인별 프로필 (예: `reddit.com → EN`, `Discord → JA`), 없으면 기본값.

## 3. 추천 스택

### 결론: Tauri v2 데스크톱 앱(코어) + 브라우저 확장(선택) 하이브리드

```
┌──────────────────── ATS Desktop (Tauri v2) ────────────────────┐
│ Rust core                                                       │
│  - 글로벌 단축키 (tauri-plugin-global-shortcut)                  │
│  - 클립보드 (tauri-plugin-clipboard-manager)                     │
│  - 키 입력 시뮬레이션 (enigo crate)                               │
│  - 포커스된 앱 식별 → 앱별 프로필 선택                             │
│  - localhost HTTP/WebSocket 서버 (확장과 통신)                    │
│                                                                 │
│ Translation core (TS 또는 Rust)                                 │
│  - TranslationProvider 인터페이스 (DeepL / MS / Google gtx ...) │
│  - 언어 감지, 캐시(LRU + SQLite), 사용량 카운터, 폴백 체인          │
│                                                                 │
│ UI (React + TS + Tailwind + Zustand)                            │
│  - 설정 창, 트레이 메뉴, 실시간 미리보기 오버레이                    │
└─────────────────────────────────────────────────────────────────┘
          ▲  ws://127.0.0.1:<port> (토큰 인증)
          │
┌─── Browser Extension (MV3, React/TS) ───┐
│ content script: 입력 감지, IME 처리,      │
│ 인라인 미리보기, Tab으로 확정              │
│ 번역 요청은 데스크톱 앱으로 위임            │
└─────────────────────────────────────────┘
```

프로젝트 이름의 "Server"와도 맞게, 데스크톱 앱이 **로컬 번역 서버** 역할을 하고 단축키 모드와 확장은 그 클라이언트가 되는 구조입니다. API 키, 캐시, 사용량, 설정이 한 곳에만 있게 됩니다.

### 왜 Tauri인가 (Electron과 비교)

| 기준 | Tauri v2 | Electron |
|---|---|---|
| 상주 메모리 | 수십 MB (OS WebView 사용) | 100MB 이상 (Chromium 내장) |
| UI 개발 | React/TS 그대로 | React/TS 그대로 |
| 네이티브 기능 | 공식 플러그인 + Rust 소량 | Node 네이티브 모듈 (`uiohook-napi`, `@nut-tree/nut-js`), 빌드 이슈가 잦음 |
| 학습 비용 | Rust 약간 (단축키/키 시뮬레이션 정도, 200~300줄 예상) | 전부 TS |

트레이에 항상 상주하는 유틸리티라 상주 비용이 중요하고, 네이티브로 필요한 부분이 작아서 Rust 부담이 제한적이라는 점에서 Tauri를 추천합니다. **Rust를 전혀 원하지 않는다면 Electron도 충분히 합리적인 선택**이며, 이 경우 번역 코어와 UI 구조는 동일하게 가져갈 수 있습니다.

### 번역 코어 설계 포인트 (유지보수용)

```ts
interface TranslationProvider {
  id: 'deepl' | 'microsoft' | 'google-gtx' | 'mymemory' | 'local';
  translate(req: { text: string; source?: string; target: string }): Promise<{ text: string; detected?: string }>;
  quota(): Promise<{ used: number; limit: number } | null>;
}
```

- 공급자 교체/폴백은 이 인터페이스 뒤에서만 일어나게 해서, 단축키 파이프라인과 확장은 공급자를 모르게 합니다 (전략 패턴).
- DeepL 사용량은 `/v2/usage`로 조회 가능하므로, 한도 90% 도달 시 자동으로 다음 공급자로 넘어가게 합니다.
- 같은 문장 재번역 방지 캐시 키: `hash(text + target + provider)`.

## 4. 단계별 로드맵

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| Phase 1 | Tauri 스켈레톤 + 단축키 일괄 번역 (DeepL Free) | 브라우저, Discord, Slack에서 Ctrl+Alt+T로 번역 치환 |
| Phase 2 | 설정 UI, 앱/도메인별 목표 언어 프로필, 공급자 폴백, 사용량 표시 | 트레이에서 설정 변경, 한도 근접 시 자동 전환 |
| Phase 3 | 브라우저 확장 + 로컬 서버 연결, 실시간 미리보기(IME 대응) | 브라우저 입력창에서 미리보기 → Tab 확정 |
| Phase 4 (실험) | 데스크톱 앱 실시간 미리보기 (UI Automation / AX API) | Discord/Slack 입력창 텍스트를 읽어 오버레이 표시 |

Phase 1만으로도 원래 목적(해외 커뮤니티 댓글 번역의 반복 작업 제거)은 모든 앱에서 해결됩니다.

## 5. 리스크와 대응

- **클립보드 덮어쓰기**: 사용자가 복사해둔 내용이 사라질 수 있음 → 백업 후 원복.
- **Ctrl+A가 입력창 밖까지 선택**: 일부 앱에서 페이지 전체 선택 → 앱별 예외 처리, 또는 "선택 영역만 번역" 단축키 별도 제공.
- **비공식 Google 엔드포인트 차단**: 기본값에서 제외, 비상 폴백으로만.
- **API 키 보관**: 로컬이지만 평문 대신 OS 키체인(`tauri-plugin-stronghold` 또는 keyring crate) 사용 권장.
- **localhost 서버 노출**: 다른 웹페이지가 로컬 포트에 요청할 수 있으므로 127.0.0.1 바인딩 + 확장 전용 토큰 + Origin 검사.

## 6. 학습 포인트 요약 (리마인드용)

1. 브라우저 확장은 브라우저 밖(Electron 데스크톱 앱)에 닿을 수 없다 → OS 레벨 프로세스가 필요하다.
2. 실시간 번역의 핵심 난제는 번역이 아니라 **입력 이벤트 처리**(IME 조합, 커서, 디바운스)다.
3. "무료 API"는 초과 시 **차단인지 과금인지**로 구분해야 한다.
4. 공급자는 인터페이스 뒤에 숨기고, 파이프라인(단축키/실시간)은 공급자를 몰라야 교체가 쉽다.
